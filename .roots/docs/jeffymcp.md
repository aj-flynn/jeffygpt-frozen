# JeffyMCP

Standalone [Model Context Protocol](https://modelcontextprotocol.io/) server that hosts JeffyGPT’s built-in tools. Other MCP clients (Cursor, Claude Desktop, etc.) can use it independently of JeffyGPT.

**Path:** `src/JeffyMCP/`

JeffyGPT is an **MCP client** only. Tool implementations live here; the API proxies LLM tool calls over MCP. Client wiring: [Infrastructure](./backend-infrastructure.md#mcp-client-layer).

## Transports

| Mode | How to run | Notes |
|------|------------|-------|
| **stdio** (default) | Prefer DLL + cwd (below); or `dotnet run --project ...` | DLL avoids restore/build noise on stdout; used by JeffyGPT when not under Aspire |
| **HTTP** | `dotnet run --project src/JeffyMCP/JeffyMCP.csproj --launch-profile http` (or `-- --http`) | Standalone listens on `http://127.0.0.1:3001`; Aspire assigns the URL via `ASPNETCORE_URLS`. `app.MapMcp()` at **root** with **stateless** Streamable HTTP (not legacy `/sse`). Unauthenticated — keep on loopback / non-external Aspire endpoints only |

Under **JeffyAspire.AppHost**, JeffyMCP always runs HTTP; JeffyGPT.Api receives `Transport=Http` + a resolved endpoint via environment overrides (committed `appsettings.json` stays stdio). HTTP mode also enables Aspire ServiceDefaults (OpenTelemetry + `/alive` / `/health`). Do **not** add ServiceDefaults on the stdio host (would risk corrupting JSON-RPC on stdout).

MCP HTTP has **no authentication**. The AppHost does not expose JeffyMCP with `WithExternalHttpEndpoints` (unlike the web frontend). Prefer binding to loopback (`127.0.0.1` / `localhost`) for local use — **not** safe on a shared or non-loopback network bind without adding auth.

JeffyGPT’s committed stdio config launches the **built DLL** (not `dotnet run`) so restore/build output does not corrupt MCP JSON-RPC on stdout:

```text
dotnet <path-to>/JeffyMCP.dll
```

with `WorkingDirectory` set to the JeffyMCP **project** folder so `appsettings.json` and relative sandbox paths resolve correctly.

## Tools

| Name | Purpose |
|------|---------|
| `get-current-time` | Current local time as JSON `{ "local": "..." }` |
| `list-document-roots` | Configured root aliases + optional description / entryPoint |
| `read-file` | Read a sandboxed text file |
| `list-files` | Non-recursive listing of allowed files in a sandbox directory |

Tools use `[McpServerToolType]` / `[McpServerTool(Name = "...")]` and are discovered via `WithToolsFromAssembly()`.

### Argument schemas

Parameter JSON Schema is generated by the C# MCP SDK from method signatures — **not** custom enum builders. `[Description]` attributes supply the fixed tool description.

| Tool | Parameters | Notes |
|------|------------|-------|
| `get-current-time` | (none) | Returns `{ "local": "<ISO-8601 with offset>" }` |
| `list-document-roots` | (none) | Returns `{ "roots": [ { "alias", "description?", "entryPoint?" } ] }` |
| `read-file` | `rootAlias` (string), `relativePath` (string) | Invalid alias / path → `{ "error": "..." }` from sandbox |
| `list-files` | `rootAlias` (string), `relativePath` (string, default `""`) | Top-level listing only; extension filter applied |

JeffyGPT’s `JsonSchemaToolArgumentValidator` checks the MCP-advertised schema (types/required). **Valid root aliases are not enum-constrained** — the sandbox enforces them.

## Configuration (`JeffyMCP:Tools`)

**File:** `src/JeffyMCP/appsettings.json`

| Setting | Description |
|---------|-------------|
| `FileSystem:Roots` | Alias → `{ Path, Description?, EntryPoint? }` |
| `FileSystem:MaxReadBytes` | Max readable file size (default 1 MiB) |
| `FileSystem:AllowedExtensions` | Extension allowlist |

**Path resolution:** Tool arguments must be relative (no `..`, no absolute/`C:` forms). Configured root `Path` values are **admin-trusted**: relative paths resolve against JeffyMCP’s content root; absolute paths (or `../` in config) widen the readable scope to that location. Treat root config and env overrides as privileged. Committed default:

```json
"docs": {
  "Path": "../../.roots/docs",
  "Description": "JeffyGPT project documentation root",
  "EntryPoint": "README.md"
}
```

With JeffyGPT spawning JeffyMCP using `WorkingDirectory: "../../JeffyMCP"` (relative to the API content root `JeffyGPT.Api`), that path reaches the repo-root `.roots/docs` folder.

Sandbox rules (tool-arg traversal/absolute paths, symlink/reparse rejection, extensions, streamed size cap) are enforced inside JeffyMCP’s `FileSystemSandbox`. Reads use a hard byte cap while streaming and re-check reparse/containment after open. IO failures return stable JSON errors without filesystem paths. Hard links remain a residual risk on writable roots.

## Using JeffyMCP from other clients

### Cursor / Claude Desktop (stdio)

From the **repository root**:

```json
{
  "mcpServers": {
    "JeffyMCP": {
      "command": "dotnet",
      "args": ["run", "--project", "src/JeffyMCP/JeffyMCP.csproj"]
    }
  }
}
```

Or, after a Debug build (matches JeffyGPT’s startup style):

```json
{
  "mcpServers": {
    "JeffyMCP": {
      "command": "dotnet",
      "args": ["src/JeffyMCP/bin/Debug/net10.0/JeffyMCP.dll"],
      "cwd": "src/JeffyMCP"
    }
  }
}
```

### HTTP

1. Start JeffyMCP: `dotnet run --project src/JeffyMCP/JeffyMCP.csproj -- --http` (or `--launch-profile http`)
2. Point clients at `http://127.0.0.1:3001` (default when `ASPNETCORE_URLS` is unset)
3. Startup **fails** if any configured URL is non-loopback unless `JeffyMCP:AllowNonLoopbackHttp=true`. HTTP MCP remains unauthenticated — keep it loopback / non-external (Aspire does not mark JeffyMCP external).

## How JeffyGPT consumes JeffyMCP

Configured under `JeffyGPT:Mcp:Servers` in the API `appsettings.json`. Default entry `Id: jeffymcp` uses stdio + the Debug DLL path. See [Development](./development.md#mcp-and-tool-configuration) and [Infrastructure](./backend-infrastructure.md#mcp-client-configuration).

### Security split

| Concern | Where |
|---------|--------|
| Which tools may run | JeffyGPT per-server `Policy.AllowAllTools` or `Policy.AllowedTools` (`McpToolBootstrapper`). An allowed MCP tool is trusted and executed. |
| Path sandbox, extensions, size | JeffyMCP `FileSystemSandbox` (JeffyMCP filesystem tools only) |
| Mutating / confirmation on in-process handlers | JeffyGPT `DefaultToolExecutionPolicy` (**deny** mutating and `RequiresConfirmation`; no confirmation UI yet). This does **not** re-check MCP tools. |

Every MCP server uses the same policy. There is no jeffymcp vs third-party split.

- `AllowAllTools: true` → every discovered tool is registered and executable
- `AllowAllTools: false` → `AllowedTools` must list at least one original tool name or API startup throws
- Tool not covered by that policy → **denied** (not registered)

The committed `jeffymcp` entry sets `AllowAllTools: true`. To allow only some tools, set `AllowAllTools: false` and list original names in `AllowedTools`.

JeffyMCP HTTP non-loopback binds require **both** `JeffyMCP:AllowNonLoopbackHttp` and `JeffyMCP:AllowUnauthenticatedNonLoopbackHttp`.

Treat tool results and prompts as untrusted. Prefer `Required: false` while evaluating a new server; leave `Enabled: false` until reviewed. Stdio child env vars cannot be set from `JeffyGPT:Mcp` config today (no `Environment` map on `McpServerOptions`).

**Deferred (not in current scope):** API authentication, JeffyMCP HTTP auth/mTLS for non-loopback binds, real user-confirmation UX for mutating tools, and per-server MCP HTTP auth headers on JeffyGPT’s client (`McpConnectionManager`).

### Bootstrap flags

| Setting | Behavior |
|---------|----------|
| All servers `Enabled: false` | Warning + empty tool catalog |
| `Required: true` + connect failure | API startup throws |
| `Required: false` + connect failure | Log and continue without that server’s tools |

## Adding a tool

1. Add a class under `Tools/` with `[McpServerToolType]` and `[McpServerTool]`.
2. Return structured JSON strings (not prose).
3. Unit-test under `tests/JeffyMCP/JeffyMCP.Tests/`.
4. Restart JeffyGPT (or reconnect the MCP client) so discovery picks up the tool.

How to use those tools from the chat: [Using JeffyGPT](../../.userdocs/user-guide.html#tools).

## Debug vs Release DLL path

JeffyGPT’s committed config points at `bin/Debug/net10.0/JeffyMCP.dll`. For Release, change the Arguments path (or launch by project). The API csproj references JeffyMCP with `ReferenceOutputAssembly="false"` so a normal `dotnet build` of the API also builds JeffyMCP.

If startup fails with “Required MCP server 'jeffymcp' failed to connect” or “entry point was not found”, build JeffyMCP / the API and confirm the DLL path and `WorkingDirectory`.
