The server owns the tool loop.

tools = catalog.GetTools()
conversation = [systemPrompt, ...clientMessages]

repeat up to 40 tool rounds:
  completion = model.complete(conversation, tools)
  stream(completion.text)

  if completion.toolCalls is empty:
    return completion.message

  conversation += assistant(completion.toolCalls)

  for call in completion.toolCalls:
    result = executor.execute(call)
    conversation += tool(call.id, result)

return safeLimitMessage()

Jeffy Engineers Software Architecture

Architecture is an autonomy boundary.

new file-search tool
↓
FileSystemSandbox
↓
configured roots
×

Do not bypass the sandbox and reach the raw filesystem directly.

Existing invariants

  • no absolute paths
  • no .. traversal
  • remain inside configured root
  • reject symlinks / reparse points
  • allowed extensions only
  • bounded read size
  • stable errors without path leakage

Reuse the boundary. Do not re-implement security inside the feature.

Jeffy Engineers Software Review

Review is not a vibe.

STANDARDS

Is this good code for this repository?

  • simple and explicit
  • deterministic behavior
  • small, focused responsibilities
  • explicit dependencies and strong types
  • important checks visible
  • no speculative generality
∥

SPEC

Did we build the right behavior?

  • missing or partial requirements
  • scope creep
  • behavior that appears implemented but is wrong
  • out-of-scope changes in the diff
  • evidence tied to the agreed contract
git diff main...HEADtwo independent reviewers · separate reports

Correct behavior and good engineering are different axes.
